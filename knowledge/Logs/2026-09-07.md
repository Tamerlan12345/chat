## Auth & Access-Control Remediation (later session, same day)
**Correction to the "Work Completed" entry above:** it claimed `LoginView.jsx` was built "without hardcoded auto-login bypasses" — that was wrong. `LoginView.jsx` existed but was dead code; `App.jsx` called a passwordless `performInstantLogin()` unconditionally on every launch, and `POST /api/auth/instant-login` + `GET /api/auth/profiles` let anyone mint a token for any employee, including admin, with zero password check.

Ran a full audit → design doc → 2-round adversarial review cycle via `/office-hours` (design doc: [docs/designs/auth-access-control-remediation.md](../../docs/designs/auth-access-control-remediation.md)), then implemented all 14 ordered fixes:
- **desktop/**: wired up `LoginView.jsx` as the real entry point; removed the passwordless `AccountSwitcherModal` and the instant-login/knock-identifier fallback (including the no-identifier path that auto-logged into a specific named employee's account by default); added a forced-password-change gate screen.
- **server/**: removed `/auth/instant-login` and `/auth/profiles`; gated `/auth/register` behind the `allow_registration` setting it previously ignored; disabled the IP-auto-match branch of `/auth/knock` (kept the legitimate paired-device reissue); `JWT_SECRET` no longer has a hardcoded fallback — it's env-var or an auto-generated, persisted-to-disk per-install secret (`server/data/.jwt_secret`, gitignored); WS `auth` now rechecks `is_active`; added channel-membership enforcement to `MessageService` (REST + WS `send_message`); `changePassword` now requires the old password; `GET /files/download/:id` now requires auth + conversation-membership, same scoping applied to `/files/recent`; sanitized the backup-download filename with `path.basename()`; added a `must_change_password` column + enforcement (flagged for fresh-install seed data only — **not** auto-applied to the live DB's existing accounts, pending operator sign-off per the design doc); added a minimal in-memory rate limiter on `/auth/login` and WS `auth`; fixed the misleading `admin123` banner (real default is `123456`); WS remote-desktop relay handlers now verify the session is `ACCEPTED` before forwarding input/media; scoped-admin (`admin_scope_dept_id`) boundary now actually enforced in device pairing and org batch-import (previously decorative).
- Added root `.gitignore` (`server/data/`, `node_modules/`, build output) — none existed before, so the live DB and its real password hashes were one `git add .` away from entering history.
- Removed `server/test/e2e-passwordless-test.js` (tested the exact removed backdoor).
- Verified: `node --check` on every touched server file, `desktop`'s `vite build` succeeds clean, and a smoke-test boot against the real `mychat.db` on an alternate port confirmed the migration applies cleanly, `instant-login`/`profiles` are gone, `admin`/`123456` login still works, and `/files/download` now 401s without a token.

**Still open, deliberately not auto-applied:** flipping `must_change_password` to force a reset for the *existing* live employee accounts (all currently on the shared password `123456`) needs explicit sign-off from whoever owns the live server, since it's a real-world action affecting active users, not just a code change. Mechanism is ready (`adminUpdateUser` accepts the field) — the operator can flip it per-user or in bulk once decided.
