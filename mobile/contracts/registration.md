# Самостоятельная регистрация, удаление аккаунта, жалобы и блокировки

Контракт для iOS (App Store: 5.1.1(v) удаление аккаунта, 1.2 жалобы/блокировки) и Android. Существующий вход администраторских учётных записей (`POST /api/auth/login`) не меняется. Все тексты ошибок — по-русски, в поле `error`; клиент ветвится по `code` (если он есть), а не по тексту.

Базовый путь — `/api`. Тела — JSON. Авторизация — `Authorization: Bearer <token>` там, где указано.

## 1. Регистрация по коду из письма

Двухшаговая: сначала заявка и письмо с 6-значным кодом, затем подтверждение кода.

**Главный выключатель — настройка сервера `allow_registration`** (консоль администратора; по умолчанию `false`). Выключена — `request` и `verify` отвечают 403 `REGISTRATION_DISABLED` всем, в том числе адресам из списка разрешённых: список решает только «сразу или на рассмотрение» внутри включённой регистрации. Код, выданный до выключения, учётную запись не создаёт (и не тратится: после включения его можно предъявить снова, пока он жив). Клиент узнаёт состояние заранее из `GET /api/settings/info` → `allow_registration` (boolean): при `false` вход в регистрацию скрыт или недоступен; если сервер всё же ответил `REGISTRATION_DISABLED`, клиент показывает текст `reg.disabled` из `copy-ru.md`.

Порядок проверок в `request`: выключатель → поля → почта настроена → пределы (IP, e-mail, общий) → занятость логина/e-mail → ёмкость. Ответы ниже перечислены полностью; клиент ветвится по статусу и `code`.

### 1.1 `POST /api/auth/register/request` (без токена)

Запрос:

```json
{ "email": "ivan@example.com", "username": "ivanov", "displayName": "Иван Иванов", "password": "..." }
```

- `username` — 3–64 символа `[A-Za-z0-9._-]` (как у логина администратора), регистр не различается при проверке занятости;
- `password` — политика паролей сервера (как при смене пароля);
- `email` — один адрес ASCII, до 254 символов; сервер приводит к нижнему регистру;
- `displayName` — до 100 символов, непустой.

Ответы:

| Статус | Тело | Когда |
|---|---|---|
| 202 | `{ "status": "code_sent", "registrationId": "<строка>", "expiresInSec": 600 }` | письмо с кодом отправлено |
| 400 | `{ "error": "..." }` (без `code`) | не прошла проверка полей (текст описывает поле) |
| 403 | `{ "error": "Регистрация сейчас закрыта. Обратитесь к администратору.", "code": "REGISTRATION_DISABLED" }` | `allow_registration` выключена (проверяется первой) |
| 409 | `{ "error": "Этот логин уже занят", "code": "USERNAME_TAKEN" }` или `{ "error": "Этот email уже зарегистрирован", "code": "EMAIL_TAKEN" }` | логин или e-mail уже заняты |
| 429 | `{ "error": "...", "code": "RATE_LIMITED" }` + `Retry-After` (секунды) | предел по IP (10/ч), по e-mail (3/ч), общий предел сервера (по умолчанию 60 **отправленных писем** с кодом в час со всех адресов; отказы 400/409 и неудавшееся письмо его не тратят) или слишком много незавершённых заявок |
| 503 | `{ "error": "Отправка почты не настроена", "code": "EMAIL_NOT_CONFIGURED" }` | на сервере не настроен SMTP. Серверы до этой версии отвечали без `code` — клиент считает 503 без `code` тем же случаем |
| 503 | `{ "error": "Не удалось отправить письмо", "code": "EMAIL_SEND_FAILED" }` | сбой отправки письма; заявка не сохраняется |
| 503 | `{ "error": "Сервер сейчас занят. Повторите через несколько секунд.", "code": "BUSY" }` + `Retry-After` | все слоты расчёта хэша пароля заняты (тот же предел, что у входа) |
| 503 | `{ "error": "...", "code": "PASSWORD_HASH_BUSY" }` + `Retry-After` | очередь расчёта хэша пароля переполнена |
| 500 | `{ "error": "Не удалось обработать запрос. Повторите позже." }` | внутренняя ошибка |

Ответ **не раскрывает**, входит ли адрес в список разрешённых. `registrationId` — непрозрачная строка; код живёт 10 минут, 5 попыток, одноразовый. Повторный `request` для того же e-mail заменяет предыдущую незавершённую заявку (старый код перестаёт действовать).

### 1.2 `POST /api/auth/register/verify` (без токена)

Запрос: `{ "registrationId": "<из request>", "code": "123456" }`

| Статус | Тело | Когда |
|---|---|---|
| 200 | **ровно как успешный вход**: `{ "user": { ... }, "token": "..." }` | адрес в списке разрешённых: учётная запись активна сразу |
| 202 | `{ "status": "pending" }` | адреса нет в списке: учётная запись создана в состоянии «на рассмотрении», токена нет |
| 400 | `{ "error": "Неверный код", "code": "CODE_INVALID", "attemptsLeft": 3 }` | код не подошёл, попытки ещё есть |
| 400 | `{ "error": "Неверный код", "code": "CODE_INVALID" }` (**без** `attemptsLeft`) | код не из 6 цифр или `registrationId` не той формы — попытка не засчитывается |
| 403 | `{ "error": "Регистрация сейчас закрыта. Обратитесь к администратору.", "code": "REGISTRATION_DISABLED" }` | `allow_registration` выключена; код не тратится |
| 409 | `{ "error": "...", "code": "USERNAME_TAKEN" }` или `"code": "EMAIL_TAKEN"` | логин или e-mail заняли, пока шло подтверждение; код **не** сгорает (пока жив), но заявку с тем же логином/адресом придётся подать заново |
| 410 | `{ "error": "...", "code": "CODE_EXPIRED" }` | код истёк, уже использован, попытки исчерпаны или `registrationId` неизвестен (все случаи неразличимы) |
| 429 | `{ "error": "...", "code": "RATE_LIMITED" }` + `Retry-After` | предел проверок по IP (60 за 10 мин), исчерпан общий бюджет неудачных проверок сервера (по умолчанию 300/ч со всех адресов; попытка не засчитывается) или слишком много заявок ждут решения администратора (код не сгорает — повторить позже) |
| 500 | `{ "error": "Не удалось обработать запрос. Повторите позже." }` | внутренняя ошибка; код не сгорает |

Общие пределы сервера настраиваются переменными окружения `REGISTRATION_GLOBAL_REQUESTS_PER_HOUR` (по умолчанию 60) и `REGISTRATION_GLOBAL_FAILED_VERIFIES_PER_HOUR` (по умолчанию 300). Исчерпание любого из них поднимает оповещение безопасности (`registration_request_flood` / `registration_code_bruteforce`) не чаще раза в час.

После 200 клиент ведёт себя как после обычного входа. После 202 показывает экран «Заявка на рассмотрении»; войти можно будет после одобрения администратором.

### 1.3 Вход для заявок

`POST /api/auth/login` с верным паролем у заявки:

| Статус | Тело |
|---|---|
| 403 | `{ "error": "Заявка на рассмотрении", "code": "ACCOUNT_PENDING" }` |
| 403 | `{ "error": "Заявка отклонена", "code": "ACCOUNT_REJECTED" }` |

Неверный пароль по-прежнему даёт обычный отказ без различий (чтобы по ответам нельзя было выяснить, какие заявки поданы). Токены у заявок не выдаются; REST и WebSocket для них недоступны (401 / закрытие сокета).

Состояние учётной записи хранится в колонке `users.approval_status`: `approved` (по умолчанию, все существующие записи), `pending`, `rejected`. Отдельной колонки `status` нет: она уже занята статусом присутствия.

## 2. Администратор (токен администратора)

| Метод и путь | Назначение |
|---|---|
| `GET /api/admin/registrations?status=pending\|rejected\|approved` | список заявок (по умолчанию `pending`); массив `{ id, username, full_name, email, approval_status, registered_at, ... }` |
| `POST /api/admin/registrations/:id/approve` | одобрить; запись активируется |
| `POST /api/admin/registrations/:id/reject` `{ "reason"?: "..." }` | отклонить, причина (до 500 символов) сохраняется в журнале аудита |
| `GET /api/admin/registration-allowlist` | `[ { id, pattern, created_at } ]` |
| `POST /api/admin/registration-allowlist` `{ "pattern": "user@example.com" \| "@example.com" }` | добавить адрес или домен (201) `{ id, pattern, created_at }`; 400 неверный шаблон; 409 если уже есть |
| `DELETE /api/admin/registration-allowlist/:id` | удалить запись: 200 `{ "success": true }`, 404 если нет |
| `GET /api/admin/reports?status=open\|closed` | жалобы пользователей (раздел 4): `[ { id, status, targetType, targetId, reason, details, createdAt, reporter: { id, name }, reportedUser: { id, name } \| null, messageText } ]`, новые первыми, до 200 |
| `POST /api/admin/reports/:id/close` | закрыть жалобу: 200 `{ "success": true }`, 404 если нет |

Все маршруты раздела — только для главного администратора, кроме `registrations` (также администратор подразделения в пределах своей области).

Отклонённый заявитель не может подать заявку повторно с тем же логином или адресом (409): запись остаётся отклонённой, пока администратор её не одобрит или не удалит.

Безопасность списка разрешённых: запись `@домен` разрешает **любой** адрес домена. Общие пределы сервера (раздел 1) ограничивают перебор кода с многих адресов, но точные адреса надёжнее доменов.

Список разрешённых при старте дополняется из переменной окружения `REGISTRATION_ALLOWED_EMAILS` (через запятую; точный адрес или `@домен`).

## 3. Удаление аккаунта

`DELETE /api/users/me` (токен) с телом `{ "password": "..." }`.

| Статус | Тело |
|---|---|
| 200 | `{ "success": true }` |
| 400 | `{ "error": "Укажите пароль" }` |
| 400 | `{ "error": "Нельзя удалить единственного администратора", "code": "LAST_ADMIN" }` |
| 403 | `{ "error": "Неверный пароль", "code": "INVALID_PASSWORD" }` |
| 429 | `{ "error": "Слишком много попыток. Повторите позже." }` + `Retry-After` |
| 503 | `{ "error": "...", "code": "BUSY" }` или `"code": "PASSWORD_HASH_BUSY"` + `Retry-After` |

Сервер отзывает все токены, отвязывает устройства и push-токены, закрывает сокеты, стирает персональные данные (логин освобождается, имя становится «Удалённый сотрудник», e-mail, телефон, должность, фото и его уменьшенные копии удаляются). Остальным рассылается `user_updated` с уже обезличенной записью (`username` вида `deleted~<id>`, без e-mail, телефона и должности, `is_active: 0`). Отправленные сообщения остаются, автор отображается как «Удалённый сотрудник». Действие необратимо. После ответа любой токен недействителен (401).

## 4. Жалобы и блокировки (токен)

`POST /api/reports` `{ "targetType": "message" | "user", "targetId": <число>, "reason": "<строка до 100>", "details"?: "<до 2000>" }` -> 201 `{ "id": <число>, "status": "open" }`. 400 при неверных полях, 404 если цель не существует или недоступна жалобщику, 429 `{ error }` при пределе (с `Retry-After` — 30 жалоб в час; без него — слишком много открытых жалоб). Дубликат от того же пользователя на ту же цель — 201 с прежним `id`. Клиенты шлют в `reason` код: `spam`, `abuse`, `inappropriate`, `threat`, `other` (сервер хранит строку как есть; консоль администратора показывает русские названия).

`POST /api/blocks` `{ "userId": <число> }` -> 201 `{ "userId": <число> }` (повтор — тоже 201); нельзя заблокировать себя (400), несуществующего (404), больше предела блокировок (400).
`DELETE /api/blocks/:userId` -> 200 `{ "success": true }` (идемпотентно).
`GET /api/blocks` -> 200 `{ "blocks": [ { "userId": 7, "displayName": "...", "createdAt": "<ISO-8601>" } ] }`.

Поведение блокировки (только личные переписки; каналы не затрагиваются):
- сообщения заблокированного **не отдаются** блокировщику: ни в `GET /api/messages/direct/:id`, ни в `/api/sync`, ни в `/api/conversations/direct`, ни по WebSocket (`new_message` не доставляется, push не отправляется);
- заблокированный не может писать блокировщику: отправка (REST и WebSocket) отклоняется ошибкой 403 `{ "error": "Сообщение не может быть доставлено", "code": "DM_NOT_ALLOWED" }` (текст не говорит о блокировке);
- блокировщик не может писать заблокированному, пока не снимет блокировку (тот же ответ);
- **правка** своего личного сообщения при блокировке в любую сторону отклоняется тем же кодом: WS-кадр `error` с `context: "edit_message"`, `code: "DM_NOT_ALLOWED"`, `retryable: false` (`message_updated` никому не уходит);
- **звонок** (`call_offer`) в любую сторону не встаёт: вызывающему — `call_unavailable` с обычной причиной «Сотрудник сейчас не в сети» (блокировку ответ не выдаёт), вызываемому — ни кадра, ни push о звонке. Вызов, который уже звонил в момент `POST /api/blocks` (в любую сторону), снимается: вызываемому — `call_end` (`reason: "unavailable"`; телефон, разбуженный push, получит его при входе вместо `call_offer`), вызывающему — `call_unavailable`;
- **«Побудка»** (`wake_send`) в любую сторону — `wake_error` с `code: "invalid_target"`;
- «печатает…» через блокировку не доходит;
- разблокировка возвращает видимость ранее скрытых сообщений.

Рекомендуемая реакция клиента: после `POST /api/blocks` убрать переписку из списка и очистить локальный кэш.
