# Векторы редьюсера доставки

Табличные тесты клиентской модели доставки сообщений — `../../delivery-state.md`. Один файл — один сценарий. Эталонный редьюсер `../../reference/delivery-reducer.mjs` проходит все векторы (`server/test/mobile-delivery-reducer.test.js` в `cd server && npm test`).

## Обязательное правило для платформ

**iOS и Android обязаны прогонять КАЖДЫЙ вектор** своим редьюсером в unit-тестах (XCTest / JUnit). Тест обходит каталог `fixtures/reducers/*.json` целиком (не по заранее заданному списку), чтобы новый вектор сразу попадал под проверку, и для каждого:

1. берёт `initialState` как есть (это полное состояние, §3 контракта);
2. последовательно применяет `events[i]`, сверяя возвращённые эффекты с `expectedEffects[i]` — **точно**: тот же порядок, те же поля и значения;
3. после последнего события сверяет каждый ключ верхнего уровня из `expectedState` с итоговым состоянием глубоким равенством (ключи, которых нет в `expectedState`, не сверяются).

Состояние и эффекты сравниваются как JSON: порядок ключей объекта не важен, порядок элементов массива важен; числа — целые; `null` и отсутствие ключа — разное. Платформа хранит модель как удобно, но для сверки проецирует её в форму контракта (§3, §3.2).

Векторы не входят в `manifest.json` и не являются ответами сервера: тесты декодирования фикстур (`fixtures/**` по манифесту) их пропускают, а `capture-fixtures.mjs --write` их не трогает.

## Формат

```jsonc
{
  "name": "05-offline-send-restart-replay-once",   // = имя файла без .json
  "description": "…",                               // что проверяет, по-русски
  "covers": ["T01", "T22", "…"],                    // ID переходов из §8 контракта
  "initialState": { /* полное состояние §3 */ },
  "events": [ { "type": "enqueue", "now": 1000, "…": "…" }, … ],
  "expectedEffects": [ [ /* эффекты events[0] */ ], [ /* events[1] */ ], … ],
  "expectedState": { "outbox": [], "messages": { … } }   // подмножество ключей верхнего уровня
}
```

- `now` — целые миллисекунды; в векторах — небольшие числа от условного нуля, не календарное время (редьюсер использует их только для сравнения и сложения).
- Серверные данные внутри событий — **в форме фикстур**: `ws.frame` — кадр как `fixtures/ws/*`, `sync_page.body` — как `http/sync.page.json`, `history_page.body` — как `http/messages.direct-page.json`, `http_send_result.body` — как `http/messages.send-direct-idempotent.json` (200/201) или `{ error, code? }`. Тест сверяет набор ключей с фикстурами.
- `client_msg_id` в векторах — UUID v4 в каноническом виде (`a0000001-0000-4000-8000-000000000001`) либо значения из фикстур.

## Покрытие

Тест требует, чтобы каждый ID таблицы переходов (`delivery-state.md` §8) был в `covers` хотя бы одного вектора, и не допускает неизвестных ID. Обязательные сценарии:

| Сценарий | Векторы |
|---|---|
| отправка без сети → перезапуск → ровно одна отправка | 05 |
| дедупликация двойного кадра / эха | 07, 08 |
| эхо до следующей записанной попытки | 09 |
| сброс пределом частоты → таймаут → повтор тем же ключом | 10 |

| отмена записи в очереди | 21, 22, 23, 38, 52, 56 |

| правка/удаление ещё не подтверждённого | 22, 24, 25, 37 |

## Изменение векторов

Векторы — часть контракта: меняет их только Integration, вместе с `delivery-state.md` и эталоном, в одном коммите. Ожидаемые эффекты и состояния пишутся по тексту контракта, а не копируются из вывода эталона.
