# Push-уведомления: раздел Android

Раздел 2 для `docs/PUSH-SETUP.md` (пишет команда Android; при слиянии переносится туда целиком).

## 2. Android

### 2.1 Как это устроено

- Firebase Messaging **всегда** входит в сборку (`firebase-bom` + `firebase-messaging`, `mobile/android/gradle/libs.versions.toml`).
- Плагин Google Services применяется **только если есть файл** `mobile/android/app/google-services.json` (`mobile/android/app/build.gradle.kts`). Файла нет — Firebase не настраивается, токена нет, приложение ничего не регистрирует: **push просто выключен**. Сборка, тесты и CI проходят без файла.
- Файл в `.gitignore` (`mobile/android/.gitignore`): это настройка проекта Firebase владельца, в репозиторий он не попадает. Секретом в строгом смысле он не является (ключ в нём — клиентский), но коммитить его не нужно.
- Приложение регистрирует токен FCM на сервере (`POST /api/devices/push-token`, `platform: "android"`, `device_id`, `app_version`) после каждого входа, при запуске с живым сеансом и при смене токена поставщиком. При выходе отдельный вызов не нужен: `/api/auth/logout` с `device_id` снимает токены этого устройства.
- Через Google проходят **только идентификаторы**. Получив data-сообщение (`CentyMessagingService`, не экспортируется), приложение само забирает текст и имя отправителя с нашего сервера токеном сеанса и показывает уведомление в канале «Сообщения». Не получилось (нет сети, сеанс истёк) — общий текст «Новое сообщение»; сообщение уже удалено — ничего. Push `read` снимает уведомление переписки; push `call` показывает «Входящий звонок» в канале «Звонки» (30 с), нажатие открывает приложение, сокет получает тот же `call_offer`.
- Нажатие на уведомление открывает переписку через неэкспортируемую `NotificationOpenActivity` и только для той учётной записи, для которой уведомление показано. При выходе и при входе другой учётной записи все уведомления снимаются.

### 2.2 Что сделать владельцу

1. В том же проекте Firebase, что и для сервера (раздел 1.1), откройте Android-приложение с идентификатором пакета **`com.openmychat.mobile`** (`applicationId` в `mobile/android/app/build.gradle.kts`). Отпечаток SHA-1 для FCM не нужен.
2. «Project settings → General → Your apps → google-services.json» — скачайте файл.
3. Положите его в `mobile/android/app/google-services.json` **на машине или в CI, которые собирают релиз**. Не коммитьте: файл в `.gitignore`.
   - В CI: сохраните содержимое как секрет репозитория (например, `ANDROID_GOOGLE_SERVICES_JSON`) и перед сборкой запишите его в этот путь шагом `echo "$ANDROID_GOOGLE_SERVICES_JSON" > mobile/android/app/google-services.json`. Пока секрета нет, шаг должен ничего не делать — сборка останется без push.
4. Соберите релиз (`assembleRelease` / `bundleRelease`) — плагин применится сам, потому что файл на месте.
5. На сервере должны быть заданы учётные данные FCM (раздел 1.1): без них сервер отвечает `push_enabled: false` и ничего не шлёт, даже если приложение зарегистрировало токен.

### 2.3 Проверка (не на рабочем сервере)

1. Отладочная сборка ходит на dev-стенд (`https://10.0.2.2:8443`), а он намеренно не берёт `PUSH_*` из окружения — для проверки push нужен **отдельный** сервер с ключами (раздел 4). Отладочную сборку можно направить на него: `./gradlew assembleDebug -Pcentychat.serverUrl=https://<тестовый-хост>`. Рабочий `centychat-production` для проверки не использовать.
2. Эмулятор — образ **с Google Play** (Google APIs), иначе FCM не работает.
3. Войдите, разрешите уведомления (Android 13+ спрашивает после входа), сверните приложение.
4. Проверьте по разделу 4: уведомление о сообщении с именем и текстом; нажатие открывает переписку; прочтение на компьютере снимает уведомление; после выхода уведомления не приходят и показанные исчезают.
5. Журнал: `adb logcat | grep -i firebase`. Без файла конфигурации при запуске будет строка Firebase о том, что приложение не инициализировано, — это ожидаемо (push выключен).

### 2.4 Что пока не сделано

- Полноэкранный экран входящего звонка (`CallStyle`, full-screen intent) и микрофон для звонков в фоне (foreground service типа `microphone`): сейчас при push о звонке показывается обычное уведомление высокой важности, разговор начинается после открытия приложения.
- Значок (badge) не выставляется: счётчик приложение считает само.
