# Выпуск CentyChat: чек-лист владельца

Основа — финальная перепроверка ветки `mobile-release-parity-impl` (2026-10-07) и финальная полировка `fix/final-polish`. Код сервера, настольного клиента, Android и iOS согласован; ниже — что уже сделано и что остаётся сделать **вам**, по порядку.

Главное правило: **рабочий сервер (`centychat-production`) не использовать для проверок.** Railway разворачивает ветку `master` на рабочий сервер, поэтому слияние в `master` — это и есть выпуск.

---

## 1. Что уже сделано

- **Сервер**
  - Регистрация по коду из письма подчиняется выключателю `allow_registration`; есть общие пределы на коды (защита от перебора).
  - Блокировка пользователя закрывает и звонки, «Побудку», правку сообщений.
  - Удаление учётной записи не рассылает стёртые данные.
  - Код push для Android (FCM) и iOS (APNs) готов; через Google и Apple уходят только идентификаторы. Без ключей push выключен.
  - Старая форма регистрации отвечает тем же кодом `REGISTRATION_DISABLED` и тем же текстом, что и новая.
- **Контракты**: `openapi.yaml` описывает все новые адреса; 71 вектор доставки, векторы уведомлений и фикстуры проверяются на сервере, Android и iOS; `mobile/contracts/copy/ru.json` — единый источник русских текстов.
- **Настольный клиент**: причины жалоб по-русски, работающий выключатель регистрации с честными предупреждениями, согласованная работа на нескольких устройствах, канонические тексты, требование Node ≥ 22.12.
- **Android**: запросы привязаны к своей учётной записи, выход стирает секрет устройства, загрузки по 2 с повтором при временных ошибках, защищённые нажатия на уведомления, запрет незашифрованного трафика, push FCM (включается файлом `google-services.json`), выключатель регистрации, канонические тексты.
- **iOS**: Keychain доступен после первой разблокировки, запуск без сети сохраняет сеанс, манифест приватности, Info.plist и иконка без прозрачности, код push с шаблоном entitlements, запрос разрешения, переход по нажатию, фоновая досылка, блокировка поля ввода при `DM_NOT_ALLOWED`, канонические тексты.
- **CI**: `security-checks`, `mobile-android` и `mobile-ios` зелёные; мобильные проверки запускаются и при изменении `mobile/contracts/**`.

## 2. Перед слиянием в `master`

1. **CI зелёный** на последнем коммите ветки: `security-checks`, `mobile-android`, `mobile-ios`.
2. **Переменные Railway** (сервис → Variables). Проверьте каждую:
   - **Почта для кодов:** `SMTP_HOST`, `SMTP_PORT` (587, либо 465 вместе с `SMTP_SECURE=true`), `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, при желании `SMTP_REPLY_TO`.
     - Без `SMTP_HOST` или `SMTP_FROM` регистрация отвечает «почта не настроена» (503 `EMAIL_NOT_CONFIGURED`).
     - Проверку TLS отключить нельзя: у почтового сервера должен быть действительный сертификат.
   - **`REGISTRATION_ALLOWED_EMAILS`** — кому учётная запись открывается сразу после кода. Лучше **точные адреса** через запятую. Запись `@домен` допустима, но открывает любой адрес домена; остальные адреса попадают в «Заявки» на ваше решение.
   - **`DATA_DIR` НЕ должна быть задана.** Если она задана, сервер откроет пустую базу.
   - **Ключи push — по желанию.** Без них push просто выключен. Когда появятся — `docs/PUSH-SETUP.md`, раздел 1.
3. **Резервная копия** тома или базы на Railway. Миграции только добавляют данные, откат безопасен, но копия нужна всё равно.
4. Слейте ветку в `master`.

---

## 3. Сразу после развёртывания

1. В журнале запуска сервера на Railway найдите строку `[Push] …` — без ключей там «Push-уведомления выключены», так и должно быть.
2. В настольном клиенте под администратором откройте **«Консоль → Настройки»** и включите **«Самостоятельная регистрация»** («Самостоятельная регистрация сотрудников»). Делайте это только после того, как SMTP задан.
3. Запросите код регистрации на **свой** адрес и подтвердите его — так вы проверите почту и всю цепочку на одном настоящем коде.
4. Ожидаемо: монитор безопасности покажет регистрацию как «Включена» (это предупреждение по замыслу). Вместе с ней открывается и старая форма на компьютере — она создаёт только заявки «на рассмотрении».

---

## 4. Настольный клиент: сборка

Ни один CI-процесс установщик не собирает — это делается на машине выпуска.

1. Установите **Node ≥ 22.12**.
2. `cd desktop && npm ci && npm run pack` — пробная сборка без установщика. Запустите её и проверьте: галочку в «Настройках», баннер в «Заявках», переключатель «Показать полностью» в жалобах, индикатор статуса.
3. Установщик и подпись: `npm run release` (это `npm run dist` и скрипт подписи).
4. Изменения интерфейса доходят до установленных версий 1.0.x/1.1.0 с сервера, но «свёрнутое окно — не "отошёл"» требует новой оболочки: поднимите версию и опубликуйте обновление (`npm run publish:update`).

## 5. Проверки на настоящих устройствах

Всё — на **отдельном** тестовом сервере с ключами (не рабочем), см. `docs/PUSH-SETUP.md`, раздел 4.

- [ ] **Push, Android** (телефон с Google Play, сборка с `google-services.json`): приложение свёрнуто или закрыто → сообщение приходит с именем и текстом; нажатие открывает нужную переписку нужной учётной записи; прочтение на компьютере снимает уведомление; после выхода ничего не приходит, показанные исчезают; звонок показывает «Входящий звонок» на 30 с.
- [ ] **Push, iOS** (сборка с подписью разработчика и entitlements): запрос разрешения появляется один раз после входа; сообщение, нажатие и тихое снятие при прочтении работают; после выхода токен снимается. Звонки на iPhone приходят **только при работающем приложении** (PushKit/CallKit в первой версии нет).
- [ ] **Фоновая досылка**: режим полёта → отправить сообщение → свернуть → вернуть сеть. Android (WorkManager) и iOS (`BGAppRefreshTask`) отправляют его один раз, без дубля.
- [ ] **Плавность релизной сборки Android (R8)**: замерить время кадров (`adb shell dumpsys gfxinfo`) на настоящем телефоне — замеры на эмуляторе не дали уверенного ответа.
- [ ] **Звонки и «Побудка»**: двусторонний звонок телефон ↔ телефон ↔ компьютер (звук, микрофон, отключение звука, завершение с любой стороны; заблокированный не может позвонить). Звук и сигнал «Побудки» на каждом клиенте, в том числе в режиме «Не беспокоить». На Android свёрнутое во время звонка приложение теряет микрофон (Android 14+, известно).
- [ ] **Окно разрешения на уведомления**: Android 13+ спрашивает после входа (на устройстве ещё не проверялось); iOS спрашивает один раз, после отказа не спрашивает.
- [ ] Дополнительно: истёкший токен на Android (сеанс и очередь сохраняются); заблокированный iPhone во время звонка; запуск iPhone без сети; выход с неотправленными сообщениями на обоих телефонах.

## 6. Распространение

### Android

- [ ] **Подпись релиза**: `signingConfig` и проверка обязательных параметров уже добавлены. Создайте keystore **вне** репозитория, задайте `CENTYCHAT_KEYSTORE_FILE`, `CENTYCHAT_KEYSTORE_PASSWORD`, `CENTYCHAT_KEY_ALIAS`, `CENTYCHAT_KEY_PASSWORD` (или локальный `keystore.properties`), соберите подписанный выпуск и проверьте подпись на устройстве. Без этих значений release-сборка должна завершиться ошибкой.
- [ ] **Версии**: перед каждой выкладкой передавайте новые `-Pcentychat.versionCode=<положительное число>` и `-Pcentychat.versionName=<версия>`; release-сборка требует оба значения.
- [ ] **Идентификатор пакета** `com.openmychat.mobile` (у iOS — `kz.centras.centychat`). Если хотите другой — решите до первой выкладки: потом его не сменить.
- [ ] **Firebase**: `google-services.json` для `com.openmychat.mobile` на машине сборки (или секрет CI) — `docs/PUSH-SETUP.md`, раздел 2.
- [ ] **Канал**: закрытое приложение Google Play для организации (Managed Google Play) или установка через MDM.
- [ ] **Формы Play**: Data safety, обоснование `POST_NOTIFICATIONS`.

### iOS

- [ ] **Аккаунт** Apple Developer Program (или Enterprise для внутренней раздачи).
- [ ] **App ID** `kz.centras.centychat` с включённым Push Notifications; ключ APNs `.p8` на сервере.
- [ ] **Подпись и push-entitlement**: в Xcode добавьте возможность Push Notifications или задайте `CODE_SIGN_ENTITLEMENTS = Signing/CentyChat.entitlements` (`docs/PUSH-SETUP.md`, раздел 3). Увеличивайте `CURRENT_PROJECT_VERSION` перед каждой загрузкой.
- [ ] **App Store Connect**: метки App Privacy (контакты, пользовательский контент, идентификаторы, push-токен).
- [ ] Перед загрузкой: Xcode «Generate Privacy Report» по архиву.

### Оба магазина

- [ ] **Политика конфиденциальности и адрес поддержки (URL)** — их **пока нет**, магазины без них не примут приложение.
- [ ] **Демо-аккаунт** для проверяющих на доступном из интернета сервере, с заметками для проверки на английском.
- [ ] **Способ раздачи для одной компании**: iOS — Custom App через Apple Business Manager, Unlisted или только TestFlight; Android — закрытое приложение Managed Google Play. Иначе вероятен отказ по правилу «приложение для одной компании» (App Store 3.2).
- [ ] Тестовые сборки никогда не направлять на рабочий сервер: только стенд `mobile/dev` или отдельный тестовый сервер.
