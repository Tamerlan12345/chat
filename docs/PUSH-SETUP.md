# Push-уведомления: что сделать владельцу

Решение владельца P (2026-10-07): весь код push пишется сейчас, ключи появятся позже. **Без ключей push просто выключен**: сервер, приложения и CI работают как раньше, мобильные приложения узнают о новом при открытии. Этот документ — шаги владельца, чтобы push включить.

Что уходит через Google и Apple: **только идентификаторы** (тип, переписка, id сообщения или звонящего). Текст, имена и вложения приложение берёт с нашего сервера. Контракт: `mobile/contracts/push.md`.

Порядок включения:
1. Сервер: ключи FCM и/или APNs (раздел 1).
2. Android: `google-services.json` в сборку (раздел 2).
3. iOS: возможность Push Notifications и ключ APNs (раздел 3).
4. Проверка на тестовом сервере (стенде), **не** на рабочем (раздел 4).

---

## 1. Сервер

Учётные данные поставщиков задаются **только переменными окружения или файлами-секретами** — не в консоли администратора и не в базе: угнанная учётная запись администратора не должна уметь перенаправить уведомления. Нет данных — push выключен; ошибка в данных — выключен только этот поставщик, в журнал пишется предупреждение без содержимого секрета (`server/src/push/config.js`).

### 1.1 Android — Firebase Cloud Messaging (FCM HTTP v1)

1. В [Firebase console](https://console.firebase.google.com/) создайте проект (или возьмите существующий) и добавьте Android-приложение с идентификатором пакета **`com.openmychat.mobile`** (это `applicationId` в `mobile/android/app/build.gradle.kts`).
   - Обратите внимание: у iOS другой идентификатор — `kz.centras.centychat`. Если идентификаторы должны совпадать по смыслу (например, оба `kz.centras.…`), решите это **до первой загрузки в магазин**: после публикации идентификатор пакета Android сменить нельзя, а новый идентификатор — это новое приложение и новый `google-services.json`.
2. «Project settings → Service accounts → Generate new private key» — скачается JSON сервисного аккаунта. Это секрет: не коммитьте его и не пересылайте в чатах.
3. На сервере задайте **одну** из переменных:

   | Переменная | Значение |
   |---|---|
   | `PUSH_FCM_SERVICE_ACCOUNT_FILE` | путь к JSON сервисного аккаунта на сервере (предпочтительно: файл-секрет платформы) |
   | `PUSH_FCM_SERVICE_ACCOUNT_JSON` | содержимое JSON целиком (если платформа хранит секреты только строками, например Railway) |

   Сервисному аккаунту нужна роль на отправку сообщений FCM (роль по умолчанию из «Generate new private key» подходит).

### 1.2 iOS — Apple Push Notification service (APNs, ключ .p8)

1. В [Apple Developer → Keys](https://developer.apple.com/account/resources/authkeys/list) создайте ключ с включённым **Apple Push Notifications service (APNs)**. Скачайте `.p8` (скачать можно один раз) и запишите **Key ID** (10 символов).
2. **Team ID** (10 символов) — в «Membership details» аккаунта разработчика.
3. **Bundle ID** приложения CentyChat — как в App Store Connect.
4. На сервере задайте:

   | Переменная | Значение |
   |---|---|
   | `PUSH_APNS_KEY_FILE` | путь к `.p8` на сервере, **или** |
   | `PUSH_APNS_KEY` | содержимое `.p8` (PEM; переводы строк можно записать как `\n`) |
   | `PUSH_APNS_KEY_ID` | Key ID, 10 символов `A–Z0–9` |
   | `PUSH_APNS_TEAM_ID` | Team ID, 10 символов `A–Z0–9` |
   | `PUSH_APNS_BUNDLE_ID` | Bundle ID приложения: `kz.centras.centychat`. Звонки сервер умеет слать на тему `<Bundle ID>.voip` (PushKit), но приложение iOS пока VoIP-токен не регистрирует — см. раздел 3 «Чего пока нет» |

   Один ключ `.p8` работает и для обычных уведомлений, и для VoIP, и для обеих сред. Среду (`sandbox` для сборок из Xcode, `production` для TestFlight и App Store) сервер берёт из регистрации токена устройством — настройкой её не сменить.

### 1.3 Необязательные пределы

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PUSH_CONCURRENCY` | 8 | одновременных запросов к поставщикам |
| `PUSH_QUEUE_MAX` | 10000 | заданий в очереди (звонкам — резерв сверх предела) |
| `PUSH_MAX_ATTEMPTS` | 4 | попыток доставки одного уведомления |
| `PUSH_MAX_TOKENS_PER_USER` | 10 | токенов на сотрудника (устройств с push) |

### 1.4 Как понять, что включилось

При запуске сервер пишет одну строку:
- `[Push] Push-уведомления выключены: не заданы учётные данные FCM/APNs …` — ключей нет (так и должно быть до их появления);
- `[Push] Push-уведомления включены: FCM (Android, проект <id>), APNs (iOS, <bundle>) …` — включено;
- `[Push] … — FCM (Android) выключен` / `… — APNs (iOS) выключен` — ключ задан, но с ошибкой; текст говорит, что не так (без содержимого секрета).

`POST /api/devices/push-token` возвращает `push_enabled: true`, когда у сервера есть поставщик для этой платформы.

### 1.5 Безопасность

- Ключи — только в секретах платформы (Railway Variables / файлы-секреты), не в репозитории, не в `.env`, который коммитится. CI ключей не получает и в них не нуждается.
- Отзыв: удалите ключ в Firebase / Apple Developer и переменную на сервере, перезапустите сервер.
- Dev-стенд (`mobile/dev/stand.mjs`) переменные `PUSH_*` из окружения **не наследует** — случайно разослать настоящие push со стенда нельзя.

## 2. Android

### 2.1 Как это устроено

- Firebase Messaging **всегда** входит в сборку (`firebase-bom` + `firebase-messaging`, `mobile/android/gradle/libs.versions.toml`).
- Плагин Google Services применяется **только если есть файл** `mobile/android/app/google-services.json` (`mobile/android/app/build.gradle.kts`). Файла нет — Firebase не настраивается, токена нет, приложение ничего не регистрирует: **push просто выключен**. Сборка, тесты и CI проходят без файла.
- Файл в `.gitignore` (`mobile/android/.gitignore`): это настройка проекта Firebase владельца, в репозиторий он не попадает. Секретом в строгом смысле он не является (ключ в нём — клиентский), но коммитить его не нужно. Тест `PushBuildConfigurationTest` проверяет и то, и другое.
- Приложение регистрирует токен FCM на сервере (`POST /api/devices/push-token`, `platform: "android"`, `device_id`, `app_version`) после каждого входа, при запуске с живым сеансом и при смене токена поставщиком. При выходе отдельный вызов не нужен: `/api/auth/logout` с `device_id` снимает токены этого устройства.
- Через Google проходят **только идентификаторы**. Получив data-сообщение (`CentyMessagingService`, не экспортируется), приложение само забирает текст и имя отправителя с нашего сервера токеном сеанса и показывает уведомление в канале «Сообщения». Не получилось (нет сети, сеанс истёк) — общий текст «Новое сообщение»; сообщение уже удалено — ничего.
- Push `read` снимает уведомление переписки.
- Push `call` показывает **обычное** уведомление высокой важности «Входящий звонок» с именем звонящего в канале «Звонки»; через 30 с оно снимается само. Нажатие открывает приложение, и сокет получает тот же `call_offer`. Полноэкранного экрана звонка нет (см. 2.4).
- Нажатие на уведомление открывает переписку через неэкспортируемую `NotificationOpenActivity` и только для той учётной записи, для которой уведомление показано. При выходе и при входе другой учётной записи все уведомления снимаются.

### 2.2 Что сделать владельцу

1. В том же проекте Firebase, что и для сервера (раздел 1.1), откройте Android-приложение с идентификатором пакета **`com.openmychat.mobile`**. Отпечаток SHA-1 для FCM не нужен.
2. «Project settings → General → Your apps → google-services.json» — скачайте файл.
3. Положите его в `mobile/android/app/google-services.json` **на машине, которая собирает релиз**. Не коммитьте: файл в `.gitignore`.
4. Если релиз будет собирать CI: сейчас **ни один workflow этот файл не записывает** (push в CI не нужен — тесты идут без него). Для релизной сборки в CI:
   - сохраните содержимое файла как секрет репозитория, например `ANDROID_GOOGLE_SERVICES_JSON`;
   - добавьте перед сборкой шаг, который записывает секрет в `mobile/android/app/google-services.json`, **только если секрет задан** — без секрета шаг ничего не делает, и сборка остаётся без push.
5. Соберите релиз (`./gradlew bundleRelease` или `assembleRelease`) — плагин применится сам, потому что файл на месте. Подпись релиза (keystore) — отдельный шаг, см. `docs/RELEASE-CHECKLIST.md`.
6. На сервере должны быть заданы учётные данные FCM (раздел 1.1): без них сервер отвечает `push_enabled: false` и ничего не шлёт, даже если приложение зарегистрировало токен.

### 2.3 Проверка (не на рабочем сервере)

1. Отладочная сборка ходит на dev-стенд (`https://10.0.2.2:8443`), а он намеренно не берёт `PUSH_*` из окружения — для проверки push нужен **отдельный** сервер с ключами (раздел 4). Отладочную сборку можно направить на него: `./gradlew assembleDebug -Pcentychat.serverUrl=https://<тестовый-хост>`. Рабочий `centychat-production` для проверки не использовать.
2. Эмулятор — образ **с Google Play** (Google APIs), иначе FCM не работает. Лучше — настоящий телефон.
3. Войдите, разрешите уведомления (Android 13+ спрашивает после входа), сверните приложение.
4. Проверьте по разделу 4: уведомление о сообщении с именем и текстом; нажатие открывает переписку; прочтение на компьютере снимает уведомление; после выхода уведомления не приходят и показанные исчезают.
5. Журнал: `adb logcat | grep -i firebase`. Без файла конфигурации при запуске будет строка Firebase о том, что приложение не инициализировано, — это ожидаемо (push выключен).

### 2.4 Чего пока нет (осознанно)

- Полноэкранного экрана входящего звонка (`CallStyle`, full-screen intent): при push о звонке показывается обычное уведомление «Входящий звонок», разговор начинается после открытия приложения.
- Службы переднего плана для микрофона (foreground service типа `microphone`): на Android 14+ свёрнутое во время звонка приложение теряет микрофон.
- Значка (badge) на иконке: счётчик непрочитанного приложение считает само.

## 3. iOS

Код push в приложении уже есть (решение P). **Без аккаунта Apple Developer push просто выключен**: сборки для симулятора и CI подписываются без возможностей (capabilities), APNs не выдаёт токен, сервер ничего не получает — всё остальное работает как раньше.

Что уже сделано в коде (`mobile/ios`):

- **Фоновые режимы** в `Info.plist`: `remote-notification` (тихий push `read` снимает уведомление и счётчик, когда переписку прочитали на другом устройстве), `fetch` (фоновая отправка неотправленных сообщений, `BGAppRefreshTask` с идентификатором `kz.centras.centychat.delivery-flush`) и `audio` (звонки).
- **Разрешение на уведомления** спрашивается один раз — после первого входа, не при запуске. Отказ больше не спрашивается: его можно изменить в «Настройки → CentyChat → Уведомления».
- **Токен устройства** регистрируется на сервере (`POST /api/devices/push-token`) после каждого входа и запуска с живой сессией и при каждой смене токена; при выходе сервер снимает его сам (`/auth/logout` с `device_id`).
- **Среда APNs** (`sandbox` или `production`) берётся из того, как подписано приложение (профиль `embedded.mobileprovision`, поле `aps-environment`); у сборок App Store и TestFlight профиля нет — это `production`. От конфигурации сборки (Debug/Release) среда не зависит.
- **Нажатие на уведомление** открывает его переписку. В push приходят только идентификаторы (тип, переписка, id сообщения); текст и имена приложение загружает с сервера.
- **Шаблон entitlements**: `mobile/ios/Signing/CentyChat.entitlements` (только `aps-environment`). Проект на него **не ссылается** — поэтому CI и симулятор собираются без аккаунта.

Шаги владельца (нужен аккаунт Apple Developer Program, роль Admin или App Manager):

1. **Ключ APNs на сервере** — раздел 1.2 (один `.p8` на обе среды и на VoIP).
2. **App ID.** В [Certificates, Identifiers & Profiles → Identifiers](https://developer.apple.com/account/resources/identifiers/list) откройте App ID с Bundle ID приложения (сейчас `kz.centras.centychat`; если меняете — поменяйте `PRODUCT_BUNDLE_IDENTIFIER` в проекте и `PUSH_APNS_BUNDLE_ID` на сервере одинаково) и включите **Push Notifications**. Сертификаты push для ключа `.p8` не нужны.
3. **Подпись в Xcode.** Откройте `mobile/ios/CentyChat.xcodeproj`, цель **CentyChat → Signing & Capabilities**: выберите команду (Team), оставьте «Automatically manage signing».
4. **Включите entitlements** одним из двух способов (результат одинаковый):
   - нажмите «+ Capability» → **Push Notifications** (Xcode сам создаст файл entitlements и пропишет `CODE_SIGN_ENTITLEMENTS`), **или**
   - в Build Settings цели CentyChat задайте `CODE_SIGN_ENTITLEMENTS = Signing/CentyChat.entitlements` для Debug и Release.
   «Background Modes» включать не нужно — они уже в `Info.plist`.
5. **Среда.** В файле стоит `aps-environment = development`: сборки из Xcode на устройство получают токены песочницы. При экспорте архива для App Store, TestFlight или Apple Business Manager Xcode сам заменяет значение на `production` — руками менять не нужно. Приложение сообщает серверу среду из подписи, поэтому сборка Release, подписанная профилем разработчика, тоже честно скажет `sandbox`.
6. **Номер сборки** берётся из `CURRENT_PROJECT_VERSION` (Build Settings), версия — из `MARKETING_VERSION`; перед каждой загрузкой в App Store Connect увеличивайте номер сборки.
7. **Проверка на устройстве** — раздел 4. На симулаторе удалённые push не проверить надёжно; локальные уведомления (от сокета, когда приложение открыто) работают и там.

Чего пока нет (осознанно): **PushKit/VoIP и CallKit** для звонков при закрытом приложении (входящий звонок сейчас приходит, только пока приложение открыто или работает в фоне со звонком); это отдельная задача вместе с CallKit — Apple требует показывать каждый VoIP-push через CallKit.

## 4. Проверка

1. Поднимите **отдельный** сервер с ключами (не рабочий `centychat-production`): например, временную среду на Railway или локальный сервер. Dev-стенд для этого не годится — он намеренно не берёт `PUSH_*` из окружения.
2. Войдите в приложение на устройстве, разрешите уведомления, сверните приложение.
3. С другой учётной записи напишите в личную переписку: должно прийти уведомление «Новое сообщение»; нажатие открывает эту переписку.
4. Позвоните на свёрнутое приложение:
   - **Android** — приходит обычное уведомление «Входящий звонок» с именем звонящего (не полноэкранное); через 30 с оно исчезает само. Нажатие открывает приложение, и звонок можно принять.
   - **iOS** — push о звонке **не приходит**: без PushKit/CallKit приложение не регистрирует VoIP-токен, а сервер шлёт звонки только на такие токены. Звонок дойдёт до iPhone, только пока приложение открыто (или уже в фоне со звонком). Это ожидаемо для первой версии.
5. Прочитайте переписку на компьютере: уведомление на телефоне снимается (не гарантируется на iOS).
6. Выйдите из учётной записи на телефоне: уведомления на него больше не приходят (токен удаляется при выходе).
