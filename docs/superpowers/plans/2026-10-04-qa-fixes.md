### Task 1: Android — message sent without network must not vanish (QA D2)

When the device is offline (airplane mode), sending a message clears the composer but no bubble and no error appears, and the message never reaches the server, even after reconnect. Required behaviour per `delivery-state.md`: the message appears immediately as a pending bubble (client_msg_id generated up front), becomes `failed` with a visible retry action if the send fails, and is automatically re-sent (same client_msg_id, idempotent on server) when the connection is back; the user can also tap retry or delete a failed message. Persist the pending/failed state so process death does not lose it if the existing storage layer allows (look at ChatRepository / ChatViewModel / Room usage; keep scope minimal and consistent with the existing design). Relevant: `mobile/android/app/src/main/java/com/openmychat/mobile/data/repository/ChatRepository.kt`, `features/chat/ChatViewModel.kt`. Tests: unit tests with the existing fakes (`testing/Fakes.kt`) for send-failure → failed state, retry, auto-resend after reconnect, no duplicates.

### Task 2: Android — resync after reconnect (QA D1)

After a network drop and reconnect, messages that arrived during the gap are not shown in the conversation list or the open chat and the unread counters are too low until the chat is reopened. After the WebSocket re-authenticates (and on app foreground), the app must catch up using the sync endpoint (`GET /api/sync`, cursor semantics in `openapi.yaml` / `ws-protocol.md`; `SyncPage` DTO exists) or a refresh of the conversation list, merge into the local state, update unread counters and refresh the open chat. Avoid duplicate messages and avoid a refresh storm on flapping connections (coalesce). Relevant: `data/realtime/RealtimeConnectionManager.kt`, `RealtimeRepository.kt`, `ChatViewModel.kt`, `ConversationsViewModel.kt`. Tests: unit tests with fakes — gap messages appear after reconnect, counters correct, no duplicates, coalescing.

### Task 3: Android — large font clipping and search state (QA D3, D5)

D3: with system font scale 2.0 the bottom navigation labels are cut ("Объявлени", "Профиль"). Fix so labels stay readable (wrap/ellipsize properly or scale cap per Material guidance, allow two lines / smaller label) without breaking the normal layout. D5: in search, after Back the field keeps the query but shows the plain list; after "Очистить" and typing again, results appear only after tapping the field. Fix so the field state and results always agree (state hoisting / single source of truth). Also fix the trivial finding: English accessibility strings "Close sheet" / "Drag handle" → Russian string resources. Tests: unit/Compose tests following the existing ones (`androidTest` is not run locally; add JVM unit tests where the logic lives, Compose tests only if the project already has the pattern).
