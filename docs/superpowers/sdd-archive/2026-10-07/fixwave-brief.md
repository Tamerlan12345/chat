## Owner decisions (2026-10-07)
- **P (push):** write all push code now; keys come later. Without keys push is simply off — the app must build, run and pass CI with no google-services.json / no APNs entitlement. Android: Firebase Messaging behind a build-time check (plugin applied only when `app/google-services.json` exists, or equivalent), token registration via the existing server push-token API, ids-only payload → fetch content, notification tap opens the chat (validated, see Android I3), token unregister on sign-out. iOS: ask notification permission at a sensible moment (after sign-in, once), register token, `remote-notification` background mode, tap opens the chat, an entitlements file template + docs for the owner (aps-environment set at signing time), no environment guessing that breaks with no account. Document the owner's steps in docs/PUSH-SETUP.md (server lane writes it; platform lanes add their sections).
- **Q (registration switch):** `allow_registration` is the master switch for email-code registration. Off → `/auth/register/request` and `/verify` return 403 `REGISTRATION_DISABLED`; clients hide/disable the registration entry using `/settings/info` and show the canonical text if the server refuses. On → allowlisted emails activate immediately, others go pending (unchanged).
- **R (code brute force):** add global (server-wide) limits on code requests and failed verifies in addition to per-IP/per-email; domain entries in the allowlist stay.
