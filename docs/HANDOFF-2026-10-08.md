## 1. Как работали (скиллы и процесс)

- **`using-superpowers`** — проверка, какой скилл применим, перед каждой работой.
- **`subagent-driven-development` (SDD)** — основной процесс. Для каждой задачи: исполнитель (субагент, opus) → ревьюер задачи (spec + качество, opus) → до 5 раундов исправлений с узким (scoped) повторным ревью → слияние `--no-ff` в `mobile-release-parity-impl`. Раунды 1–3 — тот же исполнитель, 4–5 — новый. Решения контролёра пишутся в журнал строками `Ruling X:`, мелочи — `minor (deferred)`, отложенное — `parked`. Скрипты скилла: `C:/Users/user/.claude/skills/subagent-driven-development/scripts/review-package PLAN BASE HEAD` (пакет диффа для ревьюера), `task-brief`, `sdd-workspace`.
- **`test-driven-development`** — каждый исполнитель обязан: сначала падающий тест (лог `*-red-*.log`), потом исправление (`*-green-*.log`). Для iOS без Mac «красное» и «зелёное» — это прогоны CI (и Linux-подмножество в Docker `swift:6.1-jammy`).
- **`requesting-code-review`** — ревью задач и итоговое ревью ветки (задача 11: 5 параллельных ревьюеров по областям, затем перепроверка объединённого кода).
- **`writing-plans`** — план `2026-10-05-continuation.md` (писался в прошлом сеансе).
- Ранее для QA глобально поставлены `webapp-testing`, `agent-browser` (skills.sh).
- Параллельные «линии» в отдельных git worktree (создавать вручную `git worktree add`; `isolation: worktree` на этой машине не работает из-за регистра буквы диска): `.claude/worktrees/m-android` (`mobile/android`), `m-ios` (`mobile/ios`), `m-desktop`, `m-integration`, основной — `mobile-release-parity`.
