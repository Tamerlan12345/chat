# QA API/WS CentyChat: отчёт (ветка origin/mobile-release-parity-impl @ 3a7a9f5)

Стенд: server/ из worktree qa-api, PORT 4102, SQLite во временном каталоге, случайный JWT_SECRET, TRUSTED_PROXY_IPS=127.0.0.1 (X-Forwarded-For для разведения IP-пределов).
Почта: настоящий SMTP-приёмник (smtp-server + mailparser, вне репозитория) на 127.0.0.1:2525 с STARTTLS; локальный CA + сертификат для localhost, доверие только через NODE_EXTRA_CA_CERTS процесса сервера. Настоящий mailer отправил настоящие письма (tls=true на стороне приёмника).
Сценарии: скрипты Node в scratchpad (reg.js, reg2.js, safety.js, extra.js, f.js). Итог: около 180 автоматических проверок, 3 найденных дефекта (исправлены), 0 открытых; заблокировано/не проверено: push (см. ниже).

## Дефекты

| ID | Серьёзность | Описание | Статус |
|---|---|---|---|
| D1 | Средняя | `POST /api/admin/registrations/:id/reject` применялся к любой учётной записи, в т.ч. действующей и к самому администратору (id=1): ставился approval_status='rejected', токены отзывались, админ терял доступ к серверу без защиты LAST_ADMIN; WS отклонённого активного пользователя оставался открытым. Повтор: админ-токен, `POST /api/admin/registrations/1/reject` -> 200, `GET /auth/me` -> 401 | Исправлено: rejectUser действует только на pending/rejected, иначе 400 «Заявка не найдена»; тест `reject применим только к заявке` |
| D2 | Низкая | WS `typing` проходил через блокировку в обе стороны (блокировщик видел «печатает…» заблокированного), вопреки контракту | Исправлено: typing подавляется при блокировке; тест `«печатает…» не доходит через блокировку` |
| D3 | Низкая | `POST /api/blocks {"userId":[1]}` -> 201 и блокировал пользователя 1 (Number([1])===1); так же targetId в жалобах | Исправлено: идентификатор — только число или строка цифр; тест `идентификатор — только число или строка цифр` |

## Наблюдения (без дефектов)

- 409 USERNAME_TAKEN/EMAIL_TAKEN раскрывают занятость логина и e-mail (заложено контрактом); список разрешённых при этом не раскрывается.
- GET /api/users/:id для удалённого возвращает 200 с `deleted~<id>` и «Удалённый сотрудник» (персональных данных нет).
- Заблокированный видит прежнюю историю с блокирующим (контракт скрывает только у блокирующего).
- При параллельной подаче заявок с одного IP свыше 3 одновременных scrypt возвращается 503 BUSY: офис за одним NAT может на это натолкнуться (клиенту стоит повторять по Retry-After).
- reject уже отклонённой и approve отклонённой заявки допускаются (admin может передумать).
