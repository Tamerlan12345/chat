## Замечания (дефекты низкой серьёзности, не исправлялись)

1. LOW. Превью диалога после удаления последнего сообщения. Шаги: удалить последнее сообщение в личной переписке, посмотреть список "Диалоги". Ожидание: понятное превью ("Сообщение удалено") или предыдущее сообщение. Факт: "Нажмите для беседы" и время удалённого сообщения. Причина: сервер при мягком удалении ставит text='' (message.service.js deleteMessage), getDirectConversations берёт last.text, клиент (App.jsx ~2409) подставляет заглушку.
2. LOW. Админ не видит новые заявки на регистрацию вживую. Сервер шлёт `registration_pending` (broadcastToAdmins, api/index.js:639), но клиент этот кадр не обрабатывает (нет в renderer). Шаги: админ вошёл в десктоп, открыл Консоль → Заявки; зарегистрировать нового пользователя через /api/auth/register; карточки нет, список и бейдж не обновляются до повторного открытия консоли.
3. INFO. Сессия не всегда переживает принудительное убийство процесса (см. сценарий 19); для пользователя это сценарий аварийного завершения Windows/питания. Не воспроизведено без taskkill /F; если важно — проверить на установленной сборке закрытием через трей/Выход.
4. INFO (не дефект). Панель чата остаётся открытой на вкладке "Каналы", поэтому клиент считает чат просматриваемым (viewing direct:N, notify=false) — согласовано с дизайном multi-device.
