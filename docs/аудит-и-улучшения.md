# Аудит: что сломано, что исправлено, что осталось

Разбор по сценариям — от установки до разговора. Правило одно: если дефект
подтверждён, он исправлен и закрыт тестом; если не подтверждён, он назван
предположением.

---

## 1. Установщик

### Найдено и исправлено

**Пересобранные дистрибутивы оставались без подписи, а сборка сообщала обратное.**
electron-builder подписывает через `signtool.exe` из Windows SDK. На машине
сборки его нет. При этом в журнале честно пишется `signing with signtool.exe`,
сборка завершается успешно — и файлы выходят неподписанными. Ошибка тихая:
узнать о ней можно было только у сотрудника, у которого Windows опять спросила
про издателя.

Подпись переведена на `Set-AuthenticodeSignature` — часть самого PowerShell, ни
SDK, ни загрузок не требует. Добавлена метка времени: без неё подпись
перестаёт считаться действительной в день истечения сертификата, и все уже
установленные копии «портятся» разом.

```
npm run release    # собрать и подписать
npm run sign       # только подписать уже собранное
```

**Сертификат ставился не в то хранилище.** Дистрибутивы подписаны сертификатом
«Centras Insurance», но он самоподписанный. На проверенной машине он лежал
только в «Доверенных издателях» (`TrustedPublisher`) и отсутствовал в
«Доверенных корневых центрах» (`Root`). Без корня цепочку доверия строить не от
чего: подпись остаётся недействительной (`Status = UnknownError`), и
предупреждение об издателе никуда не девается.

Добавлен `installer/установить-сертификат.bat` — ставит сертификат в **оба**
хранилища и тут же показывает статус подписи. С правами администратора — для
всего компьютера, без них — для текущего пользователя.

Проверить можно так:

```powershell
Get-AuthenticodeSignature '.\CentyChat-Setup-<версия>.exe' | Select Status
# до установки сертификата: UnknownError
# после:                     Valid
```

### Что это меняет и чего не меняет

| | До | После |
|---|---|---|
| «Неизвестный издатель» при запуске | есть | нет, если сертификат установлен |
| SmartScreen «Windows защитила ваш компьютер» | есть | остаётся до накопления репутации |
| Smart App Control блокирует запуск | блокирует | **блокирует по-прежнему** |

Smart App Control доверяет только удостоверяющим центрам из программы
доверенных корней Microsoft. Корпоративный сертификат туда добавить нельзя
никакими настройками — это устройство самой проверки, а не недоработка. На
компьютерах, управляемых доменом, Smart App Control отключается системой сам,
и там достаточно установки сертификата.

### Что стоит решить

Раздавать сертификат сотрудникам по одному — работа, которая повторяется с
каждым новым компьютером. Если машины в домене, тот же сертификат ставится
групповой политикой один раз на всех:
`Конфигурация компьютера → Политики → Параметры Windows → Параметры
безопасности → Политики открытого ключа → Доверенные корневые центры`.
Это пятнадцать минут и снимает вопрос навсегда.

## 2. Защита: инъекции и границы доверия

### Проверено

**SQL.** Все запросы параметризованы. Имена таблиц подставляются в текст
запроса только там, где берутся из внутреннего списка или из `sqlite_master`
после проверки. Отдельный тест (`test/sql-dialect.test.js`) следит за тем,
чтобы в запросах к хранилищу учётных записей не появился позиционный `?`:
в SQLite он работает, в PostgreSQL молча ломается — такую ошибку тестами на
запасном хранилище не поймать.

**Командная строка.** Найдена и закрыта настоящая дыра: удалённый ввод текста
собирался в команду PowerShell, а команды читаются из stdin построчно. Перевод
строки внутри текста разрывал команду надвое. Оператор с правом управления
чужим столом получал таким образом больше, чем ему выдали: не «печатать в
активное окно», а выполнять произвольные команды — в том числе когда на том
конце вообще нет открытого окна. Управляющие символы вычищаются до сборки
команды; перевод строки как «клавиша длиной в один символ» больше не проходит.

**Путь к файлу.** Скачивание резервной копии приводит имя через
`path.basename` — выйти за пределы каталога нельзя.

**Разметка.** `dangerouslySetInnerHTML`, `eval` и сборка HTML строками в
интерфейсе не встречаются вовсе: React экранирует текст сам.

**Разрешения окна.** Интерфейс приходит с сервера, то есть это удалённый код.
Задан закрытый список разрешений: микрофон и буфер обмена. Местоположение,
уведомления браузера, датчики, MIDI — отклоняются.

### Ранее закрытое, перепроверено

Хэши паролей недостижимы из админ-панели (учётные записи в отдельной базе,
`ATTACH DATABASE` запрещён); токены отзываются немедленно при смене пароля,
смене роли и отключении; счётчик неудачных входов переживает перезапуск
сервера; заголовок `X-Forwarded-For` учитывается только от доверенного узла.

## 3. Удалённый рабочий стол

### Найдено и исправлено

**Чёрный экран.** Поток приходит раньше, чем появляется сам элемент `<video>` —
до этого показана заставка «устанавливаем соединение». Присваивание источника
происходило прямо в обработчике, когда ссылки на элемент ещё нет. Оно не
срабатывало ни разу, а повторить его было некому: картинка не появлялась
никогда.

**Соединение пересоздавалось по десять раз в минуту.** Обработчик завершения
приходит из главного компонента новой функцией на каждую его перерисовку, а
перерисовывается он на каждое входящее сообщение — и держался среди
зависимостей соединения. Картинка не успевала установиться между сбросами.
Это и есть главная причина жалобы «плохое разрешение, не на весь экран»: до
приемлемого качества поток просто не доживал.

**Кандидаты соединения терялись.** ICE-кандидаты нередко приходят раньше
описания соединения. Добавить их в этот момент нельзя — вызов бросает
исключение, и кандидат пропадает навсегда. Потерянный кандидат означает
несостоявшееся соединение, а выглядит это как «висит на подключении». Теперь
они ждут в очереди.

**Движения мыши забивали канал.** Каждое из сотни событий в секунду уходило
отдельным сообщением по тому же соединению, что несёт видео сеанса и звук
разговора. Ограничено тридцатью в секунду; придержанная точка досылается при
остановке, чтобы курсор замирал там, где его отпустили.

**`alert()` при завершении сеанса** останавливал всё окно: пока не нажмут «ОК»,
не идут ни сообщения, ни звонки.

Арифметика перевода координат вынесена в отдельный модуль и покрыта тестами:
промах курсора виден только на чужом экране и только вдвоём — «кажется, чуть
левее» не тот способ находить такие ошибки.

### О выборе технологий

Ввод идёт через PowerShell и `SendInput` из `user32.dll`, а не через нативный
модуль вроде `nut.js` или `robotjs`. Причина не в удобстве: нативный модуль —
это ещё один неподписанный двоичный файл в установщике, а именно на них
спотыкается Smart App Control. `powershell.exe` подписан Microsoft и есть на
каждой машине. Ноль новых файлов — решение остаётся верным.

Картинка идёт по WebRTC с публичным STUN. Прямое соединение внутри одной
корпоративной сети устанавливается; между сетями (удалёнка) — может не
установиться, и тогда нужен TURN. Это отдельная служба и отдельные расходы;
решение имеет смысл принимать, когда такой случай действительно появится.

## 4. Звонки

### Найдено и исправлено

**Кадры разбирались вперемешку.** Двоичные сообщения приходили объектами
`Blob`, а `Blob` читается только асинхронно: пока читается один кадр, успевает
прийти следующий, и порядок теряется. Речь звучала рвано. Сокету задан режим
`arraybuffer` — разбор стал синхронным.

**Задержка росла весь разговор.** Кадры ставятся в очередь с небольшим запасом,
иначе неравномерная доставка даёт щелчки. Но у запаса не было потолка: часы
сторон идут не совсем одинаково, и за получасовой разговор расхождение в доли
процента складывается в секунды. Появился потолок в 250 мс и пересборка
очереди; счётчик пересборок виден в статистике.

**Звук рвался на каждое сообщение в чате.** Захват работал на
`ScriptProcessorNode` — это тот же поток, что и интерфейс: каждая перерисовка
React крала у него время. Переведён на `AudioWorklet`, который живёт на
отдельном звуковом потоке. Запасной путь на `ScriptProcessor` оставлен.

**Микрофон мог не запуститься вовсе.** В Electron не был задан обработчик
разрешений — поведение зависело от версии, и запрос мог отклоняться ещё до
того, как система спросит пользователя. Теперь обработчик задан явно.

**Непонятная ошибка вместо объяснения.** Если страница открыта по `http`,
Chromium прячет `navigator.mediaDevices` целиком, и сотрудник видел
«Cannot read properties of undefined». Теперь — «Звонки работают только по
защищённому соединению, обратитесь к администратору».

**Половина трафика была тишиной.** Разговор примерно наполовину состоит из
пауз. Кадры ниже порога тишины не отправляются вовсе — это самое дешёвое
сжатие, без кодека и без потери качества. Кадр укорочен с 64 до 32 мс: отклик
живее.

### О выборе технологий

Звук идёт через сервер по тому же WebSocket, что и переписка, а не напрямую
между компьютерами. В корпоративной сети прямое соединение обычно не
устанавливается: исходящий UDP закрыт, NAT симметричный. Лечится это
TURN-сервером — отдельная служба, отдельные порты, отдельные расходы. Через
сервер работает везде, где работает чат, и настраивать в сети нечего.

Плата — трафик через сервер. При 16 кГц моно это около 256 кбит/с в каждую
сторону, теперь примерно вдвое меньше за счёт пропуска пауз. Настоящее сжатие
(Opus) дало бы 24 кбит/с, но в браузере его можно получить только через
`MediaRecorder` — а он режет звук кусками по сотне миллисекунд, и для
разговора это заметная задержка. Вопрос стоит вернуть, когда одновременных
разговоров станет много.

## 5. Интерфейс

### Найдено и исправлено

**Заявки на регистрацию были недоступны.** Сервер умел их подтверждать с
первого дня, но в консоли не было ни раздела, ни кнопок: заявки копились там,
где их никто не видел. Появился раздел «Заявки» — со счётчиком у пункта меню,
таблицей и решением в два нажатия. Отказ переспрашивает.

**Кнопки, которые ничего не делали.** «Войдите в существующую» в пустом списке
конференций имела пустой обработчик. Меню «Плагины» показывало окно с текстом
«плагин активен» и на этом заканчивалось.

**Пункты меню молчали вместо объяснения.** Если роль не даёт права на звонки,
нажатие просто ничего не делало. Теперь такие пункты показаны недоступными и
называют причину.

**Скачивание резервной копии отвечало отказом.** Обычная ссылка не шлёт
заголовок с токеном, сервер отвечал 401, и кнопка выглядела сломанной.

**Студия базы данных обращалась по относительным адресам** — в режиме
разработки запросы уходили в пустоту. Пример запроса ссылался на таблицу
`users`, которой в базе переписки больше нет.

**Таблица заявок использовала класс, которого в стилях нет вовсе** — столбцы
налезали друг на друга. Найдено отрисовкой: тесты такого не видят.

---

### Профиль сотрудника

**ФИО разбиралось не в том порядке.** Хранится оно строкой «Фамилия Имя
Отчество», а форма читала первое слово как имя, остальное — как фамилию.
Сотрудник открывал свою карточку и видел фамилию в поле «Имя». Сохранение
собирало строку обратно, поэтому ошибка не портила данные — только вводила в
заблуждение, и заметить её можно было лишь глазами.

**Отчество не доходило до сохранения.** Поле было, его заполняли, и оно
пропадало. Разбор и сборка вынесены в отдельный модуль с тестами — включая
двойные фамилии и записи из одного слова.

**Пять вкладок из семи не отрисовывали ничего.** «Дом», «Личное», «Интересы»,
«Прошлое», «Дополнительно» открывали пустое окно с заголовком. Убраны.

**Поле «Пол» убрано:** колонки под него нет, значение никуда не сохранялось и
нигде не читалось.

### Прочее

**Дерево подразделений** вечно показывало «Загрузка оргструктуры…» при отказе
сервера: состояние ошибки не было предусмотрено. Теперь называет причину и
предлагает повторить.

**Поиск по конференциям** ни к чему не был подключён. Заодно подсказка «У вас
нет конференций» показывалась всегда — даже прямо над их списком.

**Кнопка «открыть карточку сотрудника»** теряла самого сотрудника: консоль
открывалась на начальной вкладке, и его искали заново руками.

## 6. Второй круг: проверка вживую

В этот раз интерфейс проверялся не чтением кода, а настоящим браузером: два
сотрудника одновременно входили, переписывались, открывали разделы, а стенд
считал каждое сообщение по WebSocket и каждый ответ сервера. Серверные дыры
сначала описаны тестом, и тест показан падающим на прежнем коде
(`test/ws-security.test.js`: 22 из 31 проверки падали до исправления).

### Нагрузка и зависания — найдено стендом

**Два открытых диалога гоняли отметки о прочтении без конца.** За 5 секунд
простоя двое сотрудников отправили серверу **9 598** отметок «прочитано»,
каждая — запись в базу по всей истории переписки. Причина в трёх местах сразу:
сервер считал прочитанными все сообщения собеседника, а не только новые, и
рассылал отметку даже когда нового не было; клиент на каждую отметку создавал
новый массив сообщений; чат на каждую перерисовку отправлял отметку снова.
Десяток таких пар занял бы сервер целиком. Исправлено с обеих сторон.

**Список диалогов переставал обновляться после входа по паролю.**
Обработчики WebSocket запоминали токен на момент создания — пустой. Каждое
входящее сообщение порождало запрос с этим токеном и молчаливый 401.

**Сотрудники, заведённые через консоль, не состояли в общих каналах.** Канал
«Общий» был у них в списке, но сервер отвечал отказом на чтение и не принимал
их сообщения. В каналы добавляли только при одобрении заявки и при импорте
оргструктуры. Исправлено для новых, а при запуске сервер сам добавляет
недостающее участие тем, кто уже заведён, — на рабочей базе такие люди есть.

**Приветствие называло сотрудника по фамилии** — «Добрый день, Иванов!»:
ФИО хранится как «Фамилия Имя Отчество», а бралось первое слово.

### Безопасность — описано тестами

| Было | Чем грозило |
|---|---|
| Рассылки уходили и в соединения, не прошедшие вход | Любой из разрешённой сети слушал события компании. Среди них — номер устройства в момент привязки, а по этому номеру сервер выдаёт недельный токен сотрудника. Вход под чужим именем без пароля |
| `GET /api/settings` отдавал настройки любому сотруднику | Токен Telegram-бота и чёрный список адресов |
| Доступ к файлу проверялся по ссылке в сообщении, а ссылку можно было вписать самому | Любой сотрудник скачивал любой файл по номеру. Вдобавок ссылка на файл №12 открывала файл №1 |
| «Ответ» на звонок принимался без вызова; отказ третьему обрывал свой разговор | Посторонний перехватывал звук чужого разговора |
| Согласие на удалённый доступ принималось от кого угодно, получатель сообщений сеанса брался от клиента | Оператор подтверждал доступ сам себе; режим «только просмотр» не ограничивал ввод на сервере |
| Разные ответы «пользователь не найден» и «неверный пароль» | Перебором выяснялся список логинов компании. Время ответа тоже различалось |
| CORS разрешал любой сайт | Страница, открытая сотрудником в офисе, обращалась к API из разрешённой сети |
| Размер сообщения WebSocket — до 100 МБ, анонимные соединения не закрывались | Память сервера |
| Удачные подключения расходовали лимит попыток | После перезапуска сервера офис за одним адресом подключался не целиком |
| Администратор подразделения мог убрать отдел у сотрудника | Сотрудник выходил из-под любого контроля |

Дополнительно: карточка коллеги и рассылки об изменении сотрудника больше не
содержат адрес входа и служебные поля; журнал ознакомления с распоряжением —
только для тех, кто их рассылает; загружаемые файлы отдаются как вложение,
а не открываются на месте; смена прав роли сразу отключает её носителей.

### Интерфейс

- Отозванный сеанс (сброс пароля, отключение, смена прав) раньше оставлял
  человека в «живом» окне со старыми данными. Теперь — экран входа с причиной.
- Выход из учётной записи оставлял в памяти открытый чат и счётчики прежнего
  сотрудника — следующий за этим компьютером видел чужую переписку.
- После обрыва связи сообщения, пришедшие за это время, не появлялись до
  перезапуска. Переподключение идёт с нарастающей паузой и досинхронизацией.
- Быстрое переключение чатов показывало историю одного под именем другого.
- Сотрудники без подразделения не показывались в «Контактах» совсем.
- Названия каналов выводились как «##Общий»; у каналов не было счётчиков.
- Уведомления не исчезали, пока в приложении что-то происходило.
- Сброс пароля в консоли вызывал `prompt()`, которого в Electron нет: кнопка
  не делала ничего. Выданный пароль пропадал через 4 секунды.
- Студия базы данных роняла всё окно у администратора подразделения.
- Все `alert()` и `confirm()` в консоли и чате заменены окнами приложения.

### Звонки и удалённый стол

Проверены тестами логики и сборкой; живой сеанс между двумя компьютерами —
нет (см. «Что осталось»).

- **Закрытие окна просмотра не завершало сеанс.** У сотрудника продолжалась
  трансляция экрана и оставался включённым ввод. Теперь любой выход —
  кнопка, обрыв, закрытие окна — завершает сеанс с обеих сторон.
- **«Только просмотр» не ограничивал ничего, кроме мыши.** Файлы и буфер
  обмена проходили. Теперь ограничение действует и у сотрудника, и на
  сервере. Буфер обмена — только после «Разрешить», и уже лежавшее в нём не
  отправляется.
- **Ввод текста шёл в PowerShell строкой.** Кириллица могла приходить
  искажённой, а типографские кавычки при определённых настройках Windows
  закрывали строку — снова путь к выполнению команд. Теперь передаются
  только коды символов. Сочетания клавиш — по физической клавише: Ctrl+C
  работает и в русской раскладке.
- **Клик уходил не туда на нескольких мониторах** — координаты считались от
  всего рабочего стола, а показывался один монитор.
- **Главный процесс доверял странице полностью.** Сейчас: переход только на
  свой сервер, внешние ссылки — в браузере, управление вводом и буфером —
  только от страницы сервера, экран отдаётся только в принятом сотрудником
  сеансе, ввод выключается при перезагрузке и падении страницы.
- **Сервер недоступен — белое окно навсегда.** Теперь страница «Нет связи с
  сервером» с автоповтором.
- **Сотрудник не видел, что его экран смотрят**, если приложение свёрнуто.
  Появился индикатор поверх окон с кнопкой «Завершить доступ».
- **Микрофон оставался включённым**, если звонок закрыли, пока шёл запрос
  разрешения; вызов без ответа звонил бесконечно; при обрыве связи у
  собеседника шёл таймер разговора, в котором никто не говорит.

### Порядок выкладки

**Сначала сервер, потом установщик.** Новое приложение отдаёт экран только
после сигнала от интерфейса, которого прежний интерфейс не посылает. Если
раздать установщик раньше, чем выложен сервер, удалённый доступ к рабочему
столу перестанет работать до выкладки. Обратный порядок безопасен.

## 7. Что осталось

По убыванию важности.

**0. Живая проверка звонков и удалённого стола на двух компьютерах.** Логика
покрыта тестами, интерфейс проверен в браузере, но Electron, микрофон,
захват экрана и ввод через `SendInput` в паре машин — нет. Установщик нужно
пересобрать и подписать (`npm run release` в `desktop`): главный процесс
изменился, а он приходит только с установкой. Известные ограничения: при
втором открытом устройстве у оператора переподключение завершает сеанс;
если Windows не сообщает номер захваченного монитора, ввод идёт на основной;
индикатор сеанса появляется, когда окно свёрнуто, но не когда оно просто
перекрыто другими окнами.

**1. Резервное копирование учётных записей** делается только средствами
PostgreSQL. На Railway это включено, для своей установки — `pg_dump` вручную.
Кнопки в панели нет, и это осознанно: выгрузка содержит хэши паролей, а
каталог копий отдаётся по HTTP.

**2. Показатели связи в сеансе** берутся из соединения, но обновляются раз в
две секунды и исчезают при разрыве. Мелочь, но выглядит как подвисание.

**3. TURN для удалённой работы.** Пока сотрудники в одной сети — не нужен. Для
работы из дома через симметричный NAT видео может не пойти.

**4. Автообновление приложения.** ~~Сейчас новая версия — это новый
установщик и обход всех рабочих мест.~~ Сделано: `electron-updater` с
раздачей с того же сервера компании, закреплённой подписью и постепенным
раскатом по процентам — см. `docs/автообновление.md` (инструкция
администратора) и `docs/superpowers/specs/2026-09-28-autoupdate-design.md`
(дизайн).

## Как проверять

```bash
cd server && npm test          # 164 теста на запасном хранилище (1 — только для PostgreSQL)
cd server && npm run test:pg   # те же 164 на настоящем PostgreSQL
cd desktop && npm test         # 127 тестов: ввод, звук, координаты, права, сеансы, звонки
cd desktop && npm run release  # собрать и подписать дистрибутивы
```

`npm run test:pg` обязателен перед выкладкой изменений, затрагивающих
хранилище: часть ошибок видна только на PostgreSQL.
